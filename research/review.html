Annotation rules — read before starting
  • Present: the candidate is expected or preferred to use the skill, including an unambiguous paraphrase. Required and preferred wording both count here.
  • Absent: the skill is not supported by the role text, is only company background, or is explicitly not required. This says nothing about a candidate’s ability.
  • Uncertain: the wording is genuinely ambiguous. Explain why; uncertain cells are excluded from scoring with coverage reported.
  • Do not infer Python just from Django/Flask, or SQL just from PostgreSQL. Generic HTTP/JSON endpoints alone do not establish REST constraints; use uncertain where necessary.
  • Read each clause: “Python required, Docker not required” supports Python only. Ignore unrelated substrings such as Java inside JavaScript.
  • For present/uncertain labels, include brief supporting quotations and skill names in the case notes. Keep notes about the job, not about a real candidate.
